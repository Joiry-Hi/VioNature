# Devlog — Web Release Build

VioNature now has a working HTML5/WebAssembly release path.

This was less about adding another weapon or boss, and more about making the whole FPS laboratory survive contact with the browser: Emscripten startup semantics, itch.io package rules, iframe sizing, browser pointer lock, fullscreen permissions, and the small pile of strange things that only happen once a native desktop game becomes a web page.

## HTML5 Build Pipeline

A new web build flow is available through:

```bash
bash scripts/build-web.sh
```

The script builds the game with Emscripten, preloads `config/` and `assets/` into `vionature.data`, and emits a browser-ready distribution under `dist-web/`.

Generated files:

| File | Purpose |
|------|---------|
| `dist-web/index.html` | Default browser entry point |
| `dist-web/vionature.html` | Alternate explicit entry point |
| `dist-web/vionature.js` | Emscripten runtime and glue code |
| `dist-web/vionature.wasm` | Compiled game code |
| `dist-web/vionature.data` | Preloaded config and asset package |
| `web-release/vionature_web.zip` | Generic web build archive |
| `web-release/vionature_itch_html5.zip` | itch.io upload archive |

The itch.io zip is intentionally flat: `index.html` sits directly at the archive root. This avoids the classic "Failed to find index.html" upload failure caused by zipping the parent folder instead of the web files themselves.

## Explicit Web Startup

The first web builds produced `.js`, `.wasm`, and `.data` files correctly, but the game did not actually start. The runtime initialized, but Emscripten did not call the C++ `main()` path in the way the native build expected.

The fix was to make startup explicit:

- `main.cpp` exposes `StartGame()` via `EMSCRIPTEN_KEEPALIVE`.
- `web/shell.html` calls `Module.ccall('StartGame')` once the runtime is initialized.
- The Web link flags use `-sINVOKE_RUN=0`, so the page no longer depends on automatic `main()` invocation.
- The `Game` instance is kept alive for the browser main loop instead of relying on a stack object that would be unsafe after returning from the startup call.

This makes the web lifecycle boring in the best possible way: load runtime, preload files, call `StartGame`, enter `emscripten_set_main_loop`.

## Canvas Scaling

The game still renders internally as a fixed 16:9 experience, but the HTML shell now scales the canvas to fit the browser window or itch.io iframe.

The shell uses a 16:9 container sized to the largest area that fits inside the current viewport. If the embed is not exactly 16:9, the page letterboxes instead of cropping the HUD or weapon viewmodel. This keeps the browser version visually faithful to the desktop build while avoiding the "only part of the screen is visible" problem.

## Pointer Lock And Fullscreen

FPS mouse input is the trickiest part of the browser port.

On desktop, the game can rely on raylib/GLFW mouse delta. In a browser, the cursor may be visually pinned to the center of the iframe, and raw position-based deltas can become unreliable. The web build now installs a small JavaScript input bridge:

- Clicking or pressing the canvas requests fullscreen.
- The same user gesture requests pointer lock.
- Mouse look is driven by `mousemove.movementX/Y`.
- Accumulated deltas are consumed by `Game::UpdateLook()` through Web-only bridge functions.
- Deltas are cleared when pointer lock or fullscreen state changes, preventing the camera from snapping upward on entry.

Browser security rules do not allow true automatic fullscreen without a user gesture, so the closest reliable flow is: click the canvas once, enter fullscreen, lock the pointer, and play.

## itch.io Notes

The web release is meant to be uploaded as:

```text
web-release/vionature_itch_html5.zip
```

Required itch.io settings:

- Mark the file as playable in the browser.
- Use the zip generated by `scripts/build-web.sh`.
- Do not zip `dist-web/` as a parent directory.
- The archive root must directly contain `index.html`.

For local testing:

```bash
cd dist-web
python3 -m http.server 8080
```

Then open:

```text
http://localhost:8080/
```

One small trap: the build script deletes and recreates `dist-web/`. If a terminal is already inside the old `dist-web` directory, Python may fail with `FileNotFoundError` because the current working directory no longer exists. Re-enter the directory after rebuilding.

## Mobile Surprise

The browser build is not a mobile port, but touch-dragging on a phone can already rotate the view in some browsers. There is no virtual movement or firing UI yet, so it is not really playable on mobile, but the fact that look input partially works suggests a possible future experiment: a lightweight touch overlay for the FPS laboratory.

## Quality Fixes Along The Way

- Fixed a native shutdown crash caused by unloading `LoadSoundAlias()` handles with `UnloadSound()` instead of `UnloadSoundAlias()`.
- Added web release documentation to `README.md`, `GAMEPLAY_GUIDE.md`, `GAMEPLAY_GUIDE_EN.md`, `CLAUDE.md`, and `web-release/`.
- Updated the build script so `web-release/vionature_itch_html5.zip` is generated every time, rather than being a one-off manual package.

## Result

VioNature can now be played as a desktop build or as an itch.io-style browser build. The web version keeps the same config-driven FPS sandbox identity: all weapons, maps, world-layer weirdness, bosses, drones, magic circles, and live-tuning remain part of the same game, just packed into a browser tab.

# Devlog — Flamethrower Overhaul & Water Droplet

## Napalm Grenade (Flamethrower Alt-Fire Rework)

The old hitscan heatwave cone has been replaced with a physics-driven napalm grenade launcher.

**The grenade** is a bouncing canister: it arcs through the air, hits the ground with configurable restitution (`napalm_bounce_restitution`), scatters horizontally on impact, rolls to a stop via friction, then detonates when its fuse expires. Contact with enemies or magic circle frames also triggers immediate detonation.

**Detonation** delivers AoE damage, spawns a lingering fire patch on the ground (reusing the ground-fire system), and applies an **Ignite** debuff to every enemy in range.

**Ignite** is a damage-over-time effect (`napalm_ignite_dps`) that deals damage per frame and spawns fire particles on the burning enemy. Crucially, ignited enemies **chain-spread** the debuff — each interval (`napalm_spread_interval`), a burning enemy ignites one nearby unignited enemy within `napalm_spread_radius`. This creates the "cleansing fire" cascade the weapon always deserved.

All parameters (speed, fuse, bounce, damage, ignite duration/DPS, spread range/cooldown) are configurable via `gameplay.cfg` under the `napalm_*` keys.

### Magic Circle Activation

Napalm canisters activate magic circles in three ways:
1. **Contact detonation** — canister touches the octahedron frame → detonates + circle activates
2. **Proximity** — canister passes near the frame during flight
3. **Explosion** — detonation blast radius overlaps a circle

An activated napalm circle periodically **launches its own napalm grenades** toward the nearest enemy (at the same 0.85s cooldown as the player), turning circles into autonomous artillery emplacements.

Glass shards now also activate circles — the circle fires `shotgunShardCount` homing shards per volley with scatter spread.

### Fire Patch Visuals

Ground fire patches now render as solid concentric cylinders (outer orange → mid gold → inner white) instead of wireframes, with a configurable height offset (`heatwave_fire_patch_height`). Height defaults to match gravity well ring positioning.

## Water Droplet (Nano Constructor Ultimate)

Hold LMB+RMB while grounded and stationary with the Nano Constructor to begin crafting a water droplet.

**Crafting** consumes one essence per interval (`water_droplet_craft_interval`, default 0.5s) until the total cost is met (`water_droplet_essence_cost`, default 10). The process produces a golden diamond wireframe in front of the player, with rainbow particle bursts each interval. Releasing the buttons pauses the craft — the semi-finished droplet persists in the world. Resume by standing near it and pressing both buttons again.

**On completion**, the droplet activates: a golden diamond that dashes at extreme speed (`water_droplet_speed`, default 80) toward the nearest enemy, dealing massive contact damage (`water_droplet_damage`, default 500) and **passing through** enemies. On asteroid maps, it maintains a minimum altitude above the surface. Each droplet leaves an 8-frame golden afterimage trail.

**Repulsion**: droplets within `water_droplet_separation_mult` radii of each other push apart, ensuring even distribution across the map.

### Per-World Altitude

The droplet's minimum altitude clamp now correctly accounts for which world (front/back) it occupies, using `IsHollowPhysicsForWorld` to select the appropriate player altitude config.

## Laser Super Mode Polish

- **Rainbow beam** now tracks the player's gun muzzle each frame — the beam sweeps as you turn, rather than staying locked at its spawn position.
- **Beam width** scales with essence consumed, controlled by dedicated config keys (`super_rainbow_beam_width_base` / `_per_essence`).
- **Damage** is now DPS-based: total damage scales with beam duration, so consuming more essence gives both a wider AND deadlier beam.
- **Muzzle glow**: during super charging, a growing sphere appears at the gun muzzle — golden-to-white while charging, rainbow-cycling when super-charged.
- **Time stop** now correctly freezes ball lightning and water droplets.

## Quality Fixes

- `ClearWorld()` now clears ball lightning, water droplets, craft sites, fire patches, and napalm grenades — no more entities persisting across map resets.
- Magic circle activation checks corrected from `activatedKind == HomingShot` (never true) to `!circle.activated` (the actual "not yet activated" flag).
- Napalm circles no longer self-destruct on their own frames.
- Droplet craft height raised so the diamond sits on the surface instead of being half-buried.
- Ball lightning flies straight (no terrain hugging) and renders at full opacity.
- Water droplet minimum altitude reduced from player-altitude to `radius + 0.2` so it can reach small enemies on asteroid maps.
